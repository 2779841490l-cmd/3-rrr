## 一、真实进展（4 条，全部成立）

1. **`定案4` 修 bug 是有效的**。`K_meas[0][1] = −0.2258` vs `K_trim[0][1] = −0.115` ⇒ **X 耦合低估 1.96 倍**，与先前独立推算的 ~2.0–2.8 倍区间吻合。这一条**独立证实了 P0-A 复盘的核心结论**。
2. **P0-B 的 `sign` 漏乘 bug 是真实存在的致命 bug**。`proj_brake` 未乘 `sign` ⇒ `x−/y−` 永不触发制动、直撞 `100 ms` 上限再被回 `u0` 拉回 0。这解释了历史上 `x−/y−` 的"永远回零"怪现象。
3. **Y 轴微步的重复性确实被攻破了**。`y+` 5 发 `{5,5,4,4,4}`、`y−` 5 发 `{−4,−4,−6,−5,−4}`，**sd ≤ 0.89 cnt，5/5 落在 2 cnt 带内**。对比旧 B1 的 `Y− 崩塌 −15.3→−7.5`，这是**质变**，不是噪声。
4. **自我否证记录诚实**。`_p1bp_r1`（14.78 cnt）与 `_p1bp_r3`（4.76 cnt）两个自家方案被判负并留档，符合 AGENTS.md 反 cherry-picking 要求。

## 二、必须修正的 4 处表述（否则后续决策会踩坑）

### 2.1 「全四方向统一参数」不成立

文档标题写"统一参数一次通过"，但表格加粗的格子实际是：

| 方向 | 实际采用的 `kick` |
|---|---|
| `x+` / `x−` | **15.0 us** |
| `y+` / `y−` | **16.5 us** |

**四个方向用了两套参数**，"统一"是错的。必须按方向分别记录配方。

### 2.2 「目标 2.1 cnt」与「PASS 带 [2.0, 5.0]」自相矛盾

[`probe_target_brake.py:63-64`](../probe_target_brake.py:63)：

```python
PASS_MEAN_LO, PASS_MEAN_HI = 2.0, 5.0
PASS_STD_MAX = 2.0
```

判据是 **"落在 2~5 cnt 的宽带里"**，不是 "命中 target_cnt"。所以：

| 方向（kick=16.5） | 实测均值 | 相对 `target=2.1` 的偏差 | 偏差 / 目标值 |
|---|---|---|---|
| `y+` | +4.40 | **+2.30 cnt** | 110 % |
| `y−` | −4.60 | **−2.50 cnt** | 119 % |

**这两格判 PASS 在工程上是不成立的**：它们说明"这条路能稳定产出 4.5 cnt 的步"，而不是"能产出 2.1 cnt 的步"。
另：`y−` 在 `kick=15.0` 时 `sd = 1.949`，距 `PASS_STD_MAX = 2.0` 只差 0.05 —— 属于擦线通过，不应写进结论。

**建议改判**：`PASS` 应改为 `|mean − target| ≤ 1.5` 且 `sd ≤ 1.0`。按此新判据，当前 8 格中 `y+`/`y−` 的 `kick=16.5` 格**不通过**，只有 `kick=15.0` 的 `y+ (+2.80, sd 0.84)` 勉强通过（偏差 0.70）。

### 2.3 「速度预测制动」名义存在、实际退化为固定延时

原始 CSV 里 **`proj_brake_cnt` 恒为 `1.000`**（42 行里除 1 行外全部是 0.9999~1.0000）。而 `vel_brake_cnt_s` 只取 `163 / 168 / 177 / 180 / 185 / 190 / 195 / 200` 这类**离散值** —— 因为 5 ms 滑窗 + 1 count 量化 ⇒ 速度分辨率只有 **200 cnt/s**。

结果：`pred_brake = proj + tau·vel = 1.0 + 0.014×{170..200} ≈ 3.3–3.8` 只能是 **3 个台阶**，几乎恒定。

⇒ 机制实际是 **"探测到累计位移 ≥ 1 cnt 后，固定延 14 ms 再刹车"**。这是合法的控制策略，但**不是文档描述的连续速度预测**，写成 `pred = proj + tau·vel` 有过度包装之嫌，审稿人会追问速度估计精度。

### 2.4 sub-100 ms 的时序预算未记录，且已被突破

`t_brake_ms`（脉冲起点 → 制动触发）实测：

| 方向 | 均值 | **最大值** |
|---|---|---|
| `x+` kick=15 | 66.6 ms | **96.19 ms** |
| `x−` kick=15 | 49.0 ms | 62.36 ms |
| `y+` kick=15 | 44.2 ms | 56.58 ms |
| `y−` kick=15 | 51.7 ms | 63.69 ms |

**`x+` 第一发 `t_brake = 96.19 ms`**，之后还有 21 ms 主动反刹 + 落定读数 ⇒ 该发总时长必然 **> 100 ms**。

⇒ **若把 P0-B 作为弹道之后的"补步"接入 `_dual_side_refine`，一次补步就吃掉 40–96 ms，两次补步 100–190 ms，`sub-100 ms` 声明直接破。**
⇒ **P0-B 只有在"取代弹道末段本身（飞行中制动）"时才有意义**；作为事后补偿则与 100 ms 目标不兼容。这是接线前必须回答的架构问题。
⇒ 另外 P1-B′ 的 20 发基准**没有报告任何时延指标**，而论文主张就是 100 ms。必须补上逐发 latency 统计。

## 三、`定案4` 本身的置信度不足（这条最容易被忽略）

```
u1 (sign=+1): J_col=(+2.072, -0.662) | d=7.45 us | R^2=0.933, res_sd=4.30 cnt
u1 (sign=-1): J_col=(+1.713, -0.397) | d=6.10 us | R^2=0.907, res_sd=4.24 cnt
u2 (sign=+1): J_col=(-1.871, -4.363) | d=5.56 us | R^2=0.931, res_sd=5.92 cnt
u2 (sign=-1): J_col=(-1.912, -3.432) | d=6.25 us | R^2=0.920, res_sd=5.04 cnt
```

1. **拟合残差 `sd = 4.24 ~ 5.92 cnt`，是 Gate 1 门禁（2.5 cnt）的 1.7~2.4 倍。**
   把 `d̂ = (6.78, 5.90) us` 与 `K_meas` 当成硬前馈写进控制律，等于**把 ±5 cnt 的不确定性固化进每一次 trim**。这解释了为什么 `_p1bp_r2` 的总误差只从 3.98 降到 3.90（−2%）—— **模型换了，但模型的误差和旧模型同量级**。

2. **u1 通道与历史数据严重冲突。**
   - 定案4：`du1 = 32 us → dx = +49.50 cnt`（死区修正斜率 2.07 cnt/us）
   - 历史定案2：`S1 +40 us → +34.6 cnt`（弦斜率 0.875 cnt/us）
   ⇒ 两者差近 **2 倍**。这不是 bug，是 **u1 增益跨会话不稳定**（预载/齿面状态不同）。

3. **结论：`K_meas` 不是"真值"，只是"更近的一次采样"。** 它和 `K_trim`、RBF 一样会过期。
   ⇒ **不允许**把 `K_meas` 硬编码进 `rect_manifold_calibrator.py` 后当成永久常量（那正是 `K_trim` 当年僵化的老路）。
   ⇒ **必须**每次开机做一次 8 发快速自校准，或至少提供一键重标定入口，并在 `_p1bp` 里检测增益漂移。

## 四、接线前的三个前置条件

| 序 | 前置条件 | 判定标准 |
|---|---|---|
| A | 统一 PASS 判据为 `\|mean − target\| ≤ 1.5` 且 `sd ≤ 1.0`，并按方向分别登记 `kick`/`hold` | `y+`/`y−` 需重调 `kick` 到能真正命中 `target`（预计 `y+` 需 `kick≈14 us`、`y−` 需 `kick≈13.5 us`） |
| B | 明确 P0-B 的**架构位置**：取代弹道末段（飞行中制动）or 事后补步 | 若为事后补步，必须先在文档里撤回 `sub-100 ms` 主张；若为取代末段，需给 `t_brake` 全分布 |
| C | 给出**逐发 latency 统计**（含 `t_brake + brake_dur + settle`） | `p50 / p95 / max`，且 `p95 ≤ 100 ms` |

**在这三条满足之前，`P0-B` 应定位为「已验证的 Y 轴微步原语」，不允许写成「KPI 达成」或用于论文。**
