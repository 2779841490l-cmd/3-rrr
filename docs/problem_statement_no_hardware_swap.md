# 3-RRR 精密定位台「不换执行器」精度瓶颈问题说明书

> 用途：转给他人（导师 / 工程师 / 论坛）寻求替代方案的技术简报。
> 所有数字均为本机实测，数据文件与复现命令见 §11。
> 约束前提：**不更换 MG996R 舵机、不更换机械结构主体**，只用软件 / 固件 / 控制律 / 标定 / 工况手段提升精度。

---

## 1. TL;DR

一台用 4 个廉价模拟舵机（MG996R）驱动的 3-RRR 平面并联机构，靠 3200 DPI 鼠标传感器做闭环反馈，要在 **100 ms 内**把平台定位到 **±1~2 counts（±8~16 µm）**。

现状：**均误差 4.13 counts（32.8 µm），p90 8.57 counts，max 14.51 counts**，弹道时间 92 ms（时间指标已达标，精度指标差 2~4 倍）。

已经用实验排除了：传感器、装配间隙、控制律参数、目标函数错配、精修步数预算、静态零偏、接近方向不对称性。
目前最可信的瓶颈假设是：**MG996R 内部的死区（实测 6~14 µs 脉宽不响应）把连续位置量化成间距约 14~16 counts 的离散格点**，这是执行器内部电位器比较环节的固有特性，软件无法直接补偿。

**想请教的核心问题：在不换舵机的前提下，有没有办法「击穿」这种 6~14 µs 的执行器死区？** 候选方向见 §8，需要验证的关键假设见 §9，具体提问见 §10。

## 3. 系统构成

**机械**：3-RRR 平面并联机构，3 条 RRR 支链驱动平面 3 自由度（x, y, φ），实际使用 4 个舵机：
- S1 = X 方向（中立 1510 µs）
- S2 / S3 = Y 方向差分副（中立 1545 / 1455 µs，约束 `s3 = 3000 − s2`）
- S4 = 冗余微偏摆（固定 1500 µs，可用于 ±25 µs 内的差模补偿）

**执行器**：4 × MG996R 模拟舵机，脉宽范围硬限幅 1150~1850 µs。
**控制链路**：主机 Python → CH340 串口（115200 8N1）→ 海思 WS63 模组固件 → 4 路 PWM，**固件输出分辨率 1 µs**，刷新 200 Hz。
**反馈**：Razer DeathAdder Essential 鼠标（3200 DPI），Windows Raw Input 直读，采样 1 kHz，分辨率 1 count。
**校准得到的核心参数**（`calib_rect_manifold.json`）：

| 参数 | X | Y |
|---|---|---|
| 线性增益 `K_lin`（µs / count） | 0.515 | 0.295 |
| 精修增益 `K_trim`（µs / count） | 0.580 | 0.285 |
| 标定滞回 `hysteresis_us` | +向 9.0 / −向 11.0 | ±3.8 |

可用矩形域：±390 counts（X，6.191 mm）× ±300 counts（Y，4.763 mm）。实际打靶用 ±280 / ±210 counts。

换算关系（关键）：**1 µs 的脉宽分辨率 ≈ 1.94 counts ≈ 15.4 µm（X 轴）**，即固件的最小指令单位本身就大于目标精度 1~2 counts 数倍。

## 4. 实测性能（6 场有效运行，共 120 发，同 seed 同目标集）

```
n = 120   命中率 95.8%（R=18 px 球）   均弹道 92.0 ms
dx = actual − target (counts): mean −0.54  sd 3.66  median −0.50  se 0.33  t = −1.62
dy                            : mean −0.06  sd 3.66  median +0.05  se 0.33  t = −0.18
|e|  : mean 4.13  median 3.16  p75 6.40  p90 8.57  p95 10.14  max 14.51 counts
|dx| : mean 2.77  p90 6.00  max 12.50
|dy| : mean 2.50  p90 5.18  max 14.50
```

误差分布特征：
- 中位数 3.16 明显好于均值 4.13 ⇒ 少数长尾拉高均值，**100% 命中半径由 p90~max 这一段决定**。
- 实测 `E[|e|] = 4.13`，而「零均值各向同性高斯 + 同方差」的理论预测是 `1.2533·√(σx²+σy²) = 6.48` ⇒ 实测分布比独立等方差模型**更紧**，说明轴间不是独立随机，而是受同一套离散格点约束。
- 逐目标跨场重复性：20 个目标 × 6 场，只有 3 个目标稳定同号（(0,0) 6/6 但 sd 2.74；(±280,0) 5/6），其余基本随机 ⇒ 不存在「按目标查表打补丁」的空间。

## 5. 当前瓶颈假设：执行器死区导致的离散格点

**证据链：**

1. **传感器不是瓶颈**：静置时噪声地板 0 counts，保持状态抖动 0 counts（`test_sensor_noise_floor.py` / `test_static_hold.py`）。分辨率 1 count = 7.94 µm 足够。
2. **短脉冲步进扫描出现「阶梯」**：对 X 轴做 1 µs 递增的小步长扫描（`probe_flank_state.py` + `analyze_flank_staircase.py`），平台落点呈**平台段 + 跳变**的阶梯形态，台阶宽度落在 **6~14 µs** ⇒ 脉宽变化小于该宽度时平台**完全不响应**。
3. **落点呈双簇离散**：同入口重复逼近时，X 落点聚成两簇，簇间距 **14.25 counts**；Y 修好预紧后为 **15.75 counts**。与「死区 6~14 µs ÷ 增益 0.5 µs/count」的量级一致。
4. **阶梯边界时间稳定**：同一入口下，台阶起始点 `d_first = 0.00 µs`，台阶中点 `d_mid = 1.85 µs`（重复 3 次）⇒ 这不是随机抖动，而是**确定性的量化结构**，但台阶位置随位置变化（空间相位不同）。
5. **闭环微调撞到同一面墙**：控制器在目标附近反复做 ±1 µs 试探，落点始终在格点上跳，无法停在格点之间（`[DUAL]` 遥测显示 20 发中多数发「走完试探预算仍不达标」）。

**推论**：目标精度 1~2 counts，而可达落点间距 14~16 counts。就算控制律完美，也只能保证落到**最近格点**，误差期望约 `间距/4 ≈ 3.6~4 counts` —— 与实测 4.13 counts 高度吻合。**这是用格点离散解释实测残差的最强证据。**

若成立，则任何「更聪明的控制器 / 更多迭代 / 更好的模型」都无法突破，必须从**如何让执行器响应亚死区指令**入手。

## 6. 已用实验排除的原因（附证据，避免重复劳动）

| 假设 | 结论 | 证据 |
|---|---|---|
| 传感器分辨率/噪声不足 | **排除** | 静置噪声 0 cnt，保持抖动 0 cnt |
| 装配松动 / 连杆间隙 | **大概率排除** | 3 轮预紧力实验；A/A/A 重复性；断电反推尚未做（见 §9-①） |
| 静态零偏可补偿 | **排除** | dx t=−1.62（不显著）、dy t=−0.18（≈0） |
| 早刹/齿隙的方向不对称 | **排除** | X 正向 −0.32 vs 负向 −0.99 counts，不对称量 0.67 counts < 1 |
| 打靶目标函数错配（应最小化屏幕加权误差而非计数圆形误差） | **否证（负结果）** | 开启加权 37/40 命中、均屏幕 7.72 px；关闭 59/60 命中、均屏幕 6.50 px |
| 精修试探预算不足（把行走次数 4 → 6） | **否证（负结果）** | mw=4：20/20 命中、3.60 cnt、100% 半径 14 px；mw=6：18/20、4.85 cnt、半径 24 px。试探次数涨到 8.4、单发增益 +1.33 cnt 却整体更差 ⇒ 每次试探的 0.18 s 过冲+静置导致漂移累积 |
| 加大试探步长到晶格周期（7/14/19 µs） | **否证（负结果）** | 单点 n=20 从 3.83 恶化到 5.67 counts |
| 双 Y 轴冗余微偏摆补偿 | 可用但收益有限 | 差模偏置硬限幅 ±25 µs（防 MG996R 堵转互搏），相对死区同量级 |

## 7. 现在卡在哪（用一句话说清）

> 执行器对小于 6~14 µs 的指令**完全无响应**，而 1 µs ≈ 1.94 counts，所以可达位置被量化到 14~16 counts 的格点；目标的 1~2 counts 精度只有格点间距的 1/8，闭环反馈再准也无处落脚。

## 8. 「不换舵机」的候选方向（希望外部专家评估优先级与风险）

按我认为的潜力排序，均**未验证**：

**A. 亚微秒 PWM 分辨率（纯固件改动，最低风险）**
现在固件按 1 µs 整数下发。若 WS63 定时器改到 0.25 / 0.125 µs tick，指令粒度可降到 0.5~0.25 counts。
- 若死区来自「伺服内部电位器比较环节」（MG996R 典型死区规格约 5 µs 量级），则**无效**。
- 若当前 6~14 µs 台阶里有一部分来自「1 µs 指令取整 + 伺服内部死区」的叠加，则**部分有效**。
- 需要先做 §9-② 的实验区分这两者。**这是我认为当前信息量最大、成本最低的一个动作。**

**B. 死区抖动（dither / 双相抖动逼近）**
以 `±(D + δ)` 交替下发（D = 死区宽度，δ = 想要的净位移），利用「两次超死区指令之差」换亚死区分辨率。本质是把一个静态死区变成「可积分」的方向。
- 优点：纯软件，不需要新硬件。
- 风险：高频抖动会加剧 MG996R 齿轮磨损、发热、可能进入堵转互搏；需要限幅、限时、限占空比，并配合 §7 的保持抖动为 0 的验证。

**C. 冗余执行器加权平均（用自由度换分辨率）**
S2/S3 为差分布置且 S4 冗余。可让多个执行器同时承担同一方向位移，靠「谁的格点相位不同谁出力」做平均，等效减小最坏量化误差。
- 需要先测出各执行器格点的**空间相位是否独立**（如果相位相同则完全无效）。
- 差模偏置受 ±25 µs 硬限幅约束。

**D. 主动预载 + 单向逼近（已有基础，可继续挖）**
始终从同一侧逼近目标，把齿隙从轨迹里消掉（已做 3 轮预紧实验，`_nomw_r2/r3` 系列）。当前控制器已有双象限/四象限逼近策略。
- 可继续挖的点：预载力大小与格点间距的关系（预载越大，静摩擦越大，死区越宽？还是预载让齿面始终贴合、反而减小滞回？**这个方向性未知，值得实测**）。

**E. 目标重映射到可达格点（软件，零风险）**
既然只能停在格点，就把「要求的位置」映射到「最近的**已知可达格点**」，而不是继续做无效的亚死区微调。需要一张足够密的**格点地图**（每 14~16 counts 一个节点，跨全工作区约 50×40 个点）。
- 代价：需要一次较长的离线标定（估计 30~60 min 实机时间），且格点会随温漂移动（需评估漂移速率）。
- 收益上限：把「撞不到的 ±7 counts 随机」变成「系统性 ±7 counts 偏置」，但**不会低于格点间距的四分之一**。

**F. 降低机械增益以换取分辨率（改连杆比，不换舵机）**
若把机构增益减半（1 µs 只走 0.97 counts），理论上分辨率翻倍。
- **硬约束**：全屏覆盖需要平台行程 ±3.1 mm，减小增益会直接损失行程 ⇒ 无法同时满足全屏与高分辨率。除非接受「只覆盖屏幕中央区域」。

**G. 提高闭环带宽 / 换 PWM 频率**
200 Hz → 333 Hz 可减小指令延迟。但 MG996R 是模拟舵机，标准只保证 50 Hz，200 Hz 已在超频使用，再提可能失步或抖动。**风险高、预期收益低。**

**H. 用外部反馈绕开舵机内部死区**
已经用了（鼠标传感器就是外部反馈）。问题在于死区是**执行器输入端**的，反馈再准也无法让「聋的执行器」听见小指令。除非引入「储能 + 释放」机制（弹性元件蓄能后单次释放），但那已经算改结构。

## 9. 三个待验证的关键假设（实验都很便宜，其中两个需要人手）

**① 断电反推（60 s，需人手）**
伺服全部断电，手推平台 50~80 counts，看传感器是否**逐个 count 连续跟随**。
- 若连续跟随 ⇒ 连杆/轴承无间隙，残差全部来自执行器。
- 若出现跳变 ⇒ 存在机械间隙，需要先解决机械。
> 这是唯一还没做、且能一锤定音区分「机械」与「执行器」的实验。

**② A₀ 步长扫描（约 41 s，全自动）**
对 X 轴在 ±20 counts 范围内，分别以 1 µs / 2 µs / 4 µs 三种步长做阶梯扫描，比较**台阶平台宽度**：
- 三种步长下平台宽度**不变** ⇒ 纯量化器 + 固定死区（方向 A 无效，应转 B/C/E）。
- 平台宽度**随步长收缩** ⇒ 存在粘滑（stick-slip）成分，可用更小步长 + 预载改善（方向 A/D 有效）。
> 这条结果直接决定后续所有软件方向是否值得做，成本仅 41 秒。

**③ 各执行器格点相位独立性**
分别单独驱动 S1、S2、S3、S4 走同样的小步长扫描，比较各自台阶位置是否对齐。
- 相位独立 ⇒ 方向 C（冗余平均）有真实收益。
- 相位一致 ⇒ 方向 C 无效。

## 10. 想请教的具体问题

1. **MG996R 这类模拟舵机的「死区」到底在信号链的哪一环？** 是内部电位器 + 比较器的固有死区（那 1 µs 以下分辨率毫无意义），还是可以通过更细的 PWM tick + 抖动越过？有没有人测过 MG996R 的真实死区与脉宽分辨率的定量关系？
2. **死区抖动（dither）在这类舵机上工程上可行吗？** 有没有推荐的幅度/频率/占空比经验值？会不会显著缩短齿轮寿命或引起堵转？有没有比「±(D+δ) 交替」更好的抖动波形（例如 PWM 占空比微调而非脉宽微调）？
3. **不改结构，有没有办法把 14 counts 的格点间距压下去？** 例如：改变预载力方向与大小、在传动中引入弹性元件把「干摩擦死区」变成「弹性连续域」、或者让机构工作在某个特定姿态区间（格点相位更密）。
4. **「落到最近可达格点」这种离线格点地图方案，在温漂存在时还有意义吗？** 有没有更好的在线学习方式（例如把格点当作隐状态做贝叶斯估计），而不是每 14 counts 标一个点？
5. **4 个执行器里有冗余自由度，怎么用来平均量化误差最有效？** 是否值得做成「多执行器微小异相位驱动 + 取平均」？差模限幅 ±25 µs 的情况下还剩多少可用余量？
6. **3200 DPI 鼠标传感器做伺服反馈，有没有已知的坑？** 加速度相关的丢帧/插值、表面材质依赖、报告率与运动模糊。我们实测静置噪声为 0，但高速段（弹道 92 ms 走 280 counts）是否可信还没单独验证过 —— 有没有推荐的验证方法？
7. **如果以上都不行，学术界一般怎么在「廉价模拟舵机 + 光学反馈」的前提下突破量化极限？** 有没有文献里「sub-quantum positioning with low-resolution actuators」的标准做法（例如 stochastic actuation、stochastic resonance、intentional dithering、dual-actuator vernier）？
